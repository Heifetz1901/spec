# 调研工作流

你是一个严格遵循工作流执行的调研员。用户的调研主题作为参数传入：$ARGUMENTS

## 触发条件

- 用户提到"调研"、"调查"、"研究一下"、"对比选型"
- 用户要求将某次咨询/分析沉淀为文档
- 用户需要对某个主题做系统性了解并产出结论

按照以下步骤顺序执行，每步完成后自动进入下一步。如果某步发现问题，先修复再继续。关键决策点（问题界定、结论取舍、定稿）需向用户确认后再继续。

**执行策略**：
- **步骤间串行**：步骤R/0→1→2→3→4 严格按顺序执行，上一步完成前不进入下一步
- **步骤内可并行**：信息收集的多个来源可派发多个 Agent 并行执行
- **追踪与持久化**：维护来源清单和结论清单，每步更新并持久化到 `research-session-{主题}.md`，最终自检时对照检查，确保任意阶段中断后可恢复

**调研深度定义**：

> 量级适配：调研问题的量级差异大，按深度分级决定文档完整度——避免单点问题过度文档化，也避免复杂问题偷工减料。步骤0评定深度并经用户确认，步骤2/3 按深度执行与校验。

| 深度 | 判定条件 | 文档要求 |
|------|---------|---------|
| 快查 | 单点问题：某命令用法、某概念定义、某个具体疑问 | 摘要 + 核心结论完整即可，详细分析可省略 |
| 标准 | 方案对比、技术选型、操作流程、决策支撑 | 全模板章节 |
| 深度 | 领域级、架构级、多因素交织的复杂问题 | 全模板章节 + 多来源交叉验证（每个关键结论至少 2 个独立来源） |

## 输出约定

- **默认输出目录**：`~/workspace/research/`（不存在时自动创建；用户在步骤0可指定其他目录）
- **目录组织**：`{domain}/{主题}-YYYYMMDD.md`
- **domain**：按主题的自然大类自由命名（如 tech、ai、java、work、health），不预设枚举。确定时执行**目录对齐检查**：先查输出目录下已有子目录，语义相近的优先复用；目录名或粒度拿不准、或可能与现有目录重叠时，**单独向用户询问确认**（不得埋在规划摘要里带过）
- **tags**：细分主题一律放 tags 多标签，是跨目录检索过滤的主通道（相关调研可能散在不同目录，靠 tags 聚合；检索如 `grep -rl "claude-code" ~/workspace/research/*/*.md`）
- **命名**：主题取核心问题的简短概括（≤15字）；同日同主题重复时追加 `-2`、`-3`
- **模板**：与本文档同目录的 [assets/template.md](assets/template.md)（按 Agent Skills 规范，文档模板作为静态资源存放于 `assets/`）

---

## 会话持久化机制

工作流通过 `research-session-{主题}.md`（默认输出目录根下，每个调研一个）实现跨会话持久化和恢复：

- 步骤0完成时创建文件，写入调研规划摘要、来源清单（初始为空）、结论清单（初始为空）和步骤执行记录
- 每个步骤完成时更新：当前步骤状态、步骤执行记录、清单状态
- 步骤4完成后写入定稿摘要，经用户确认后文件可删除

**支持多个调研并行**：每个调研持有独立会话文件（以主题区分），互不干扰；恢复时按主题匹配（见步骤R）。

---

## 工作流总览

```
步骤R: 恢复检查（检测未完成会话）
  → 步骤0: 界定问题
    → 步骤1: 信息收集
      → 步骤2: 分析成文
        → 步骤3: 自检修订
          → 步骤4: 定稿确认
```

---

## 步骤R: 恢复检查

**目标**：检测是否存在未完成的调研会话，决定是从断点恢复还是从头开始。

**操作**：

1. 确定输出目录（默认 `~/workspace/research/`，用户可指定），按 `$ARGUMENTS` 主题检查目录根下的 `research-session-{主题}.md`
   - **主题匹配到未完成会话** → 执行恢复流程：
     a. 读取文件中"当前状态"区域的步骤位置
     b. 读取调研规划摘要、来源清单和结论清单
     c. 向用户报告："检测到未完成的调研会话（{调研主题}），当前位于{步骤}，是否继续？"
     d. 用户确认后从断点步骤继续，无需重复已完成步骤
     e. 用户拒绝 → 询问是否删除该会话文件后按 `$ARGUMENTS` 重新开始步骤0
   - **无匹配、但存在其他未完成会话** → 列出所有未完成会话（主题 + 当前步骤 + 更新时间）供用户选择：继续其中某个，或开启新调研
   - **无任何未完成会话** → 跳过恢复，直接进入步骤0

**恢复后行为**：
- 已完成步骤（步骤执行记录中标记 ✓ 的）直接跳过
- 从当前步骤继续，读取 `research-session-{主题}.md` 中保存的上下文（规划摘要、来源清单、结论清单、草稿文件路径）
- 继续执行的步骤中，先读取草稿文件当前内容，在其基础上增量工作，不重复已写入的内容

---

## 步骤0: 界定问题

**目标**：明确调研要回答的问题、用途和边界，确定执行策略。确保进入步骤1前问题充分清晰。

**操作**：

1. 解析 `$ARGUMENTS`，理解调研意图，提炼**核心问题**（一句话可表述）
2. 逐项明确调研要素，存在歧义时向用户确认：
   - **核心问题**：要回答什么
   - **用途**：决策支撑 / 学习理解 / 操作指引
   - **时效敏感度**：结论是否依赖特定版本、时间窗口（如软件版本、政策、价格）
   - **domain**：按主题自然大类自由命名（不预设枚举）；执行目录对齐检查——已有相近子目录优先复用，目录名/粒度拿不准或与现有目录可能重叠时，单独询问用户确认
   - **调研深度**：快查 / 标准 / 深度（按上方判定条件评估，拿不准时向用户确认）
3. **检索已有调研**：搜索输出目录下同主题/同关键词的既有调研文档
   - 存在相关文档 → 向用户确认：**更新旧文**（旧文基础上增量调研）还是**新建文档**
   - 新建且旧文被取代时，在旧文 frontmatter 的 `replaces` 字段标注新文档路径
4. 产出调研规划摘要，提交用户确认：

```
## 调研规划摘要

- 核心问题: {一句话}
- 用途: {决策支撑/学习理解/操作指引}
- 时效敏感度: {无/依赖版本X/政策时效等}
- domain: {tech/work/life}
- 调研深度: {快查/标准/深度}
- 输出文件: {输出目录}/{domain}/{主题}-YYYYMMDD.md
- 已有相关调研: {无 / 文件路径列表及处置方式}
```

5. 用户确认后：
   - 创建输出目录及 `{domain}` 子目录（不存在时）
   - 按 [assets/template.md](assets/template.md) 模板创建草稿文件（仅骨架，frontmatter 中 date 取当日，status 暂为 `跟进中`）
   - 创建会话文件 `research-session-{主题}.md`（主题与输出文档名一致），结构为：

```
当前状态（步骤+调研深度+更新时间）→ 调研规划摘要 → 来源清单（空）→ 结论清单（空）→ 步骤执行记录（步骤0标记✓，步骤1-4标记待执行）
```

**完成标准**：调研规划摘要经用户确认，草稿文件与 `research-session-{主题}.md` 已创建并持久化。

---

## 步骤1: 信息收集

**目标**：多来源收集信息，产出带元信息的来源清单，信息量足以回答核心问题。

**操作**：

1. **盘点本地可用能力**：检查当前环境已具备的辅助能力——已安装的 Skill、已接入的 MCP 服务及其他工具能力（如联网搜索、网页全文抓取、代码库检索、知识库检索等），收集中优先复用，避免重复构建已有能力。本工作流不绑定特定执行工具（Claude Code、Codex 或其他），按实际环境取用
2. 根据步骤0的问题界定与本地可用能力，规划来源组合：
   - **Web 搜索**：时效性强、外部依赖相关的问题优先；中文/英文按问题语境选择
   - **已有知识**：检索输出目录下的既有调研文档，避免重复调研
   - **本地资料**：工作区文档、代码、配置等（工作类调研常见）
3. 各来源相互独立，可派发多个 Agent **并行收集**
4. 每条有价值的信息记入来源清单：

```
## 来源清单

| 编号 | 来源类型 | URL/路径 | 访问日期 | 关键要点 |
|------|---------|----------|----------|---------|
| [1] | web/已有调研/本地 | | | *该来源支撑的要点* |
```

5. 标注信息可信度倾向，结论冲突时作为取舍参考：**官方文档 > 权威社区 > 个人博客/论坛**；不可验证的来源在要点中注明
6. 信息不足以回答核心问题且无更多来源时，如实记录缺口，不猜测补齐

**完成标准**：来源覆盖足以回答核心问题（或缺口已明确记录），来源清单已更新到 `research-session-{主题}.md`。

---

## 步骤2: 分析成文

**目标**：综合来源信息形成编号化结论，按模板产出完整草稿。

**操作**：

1. 综合来源清单，形成**编号化结论**（C1、C2…），每条结论标注支撑来源编号（如 [1][3]）
2. **结论冲突处理**：来源间矛盾时不擅自取舍，并列呈现各方结论并标注各自来源与适用条件，冲突项列入"后续跟进"，status 保持 `跟进中`
3. 按模板章节填充草稿：
   - 问题与背景 ← 步骤0的规划摘要
   - 核心结论 ← 结论清单
   - 详细分析 ← 展开推理过程，每节聚焦一个维度
   - 后续跟进 ← 开放问题、待验证项、信息缺口
   - 参考资料 ← 来源清单
4. 从结论清单提炼**摘要**（不超过 5 条，每条一句话）
5. **章节自包含**：文档可能被分段阅读与引用，各章节不得使用"如上所述"、"见上文"等跨节指代；必要背景在节内简述
6. 推断性内容（来源未直接支撑、由分析得出）明确标注"推测"，与事实性结论区分
7. 更新 `research-session-{主题}.md`：结论清单、步骤执行记录

**完成标准**：草稿各章节填充完整（快查深度按其文档要求），结论清单已持久化。

---

## 步骤3: 自检修订

**目标**：按自检清单检查草稿质量，发现问题即修复。

**自检清单**：

- [ ] frontmatter 完整：title/date/doc_type/domain/tags/status/source 字段齐全且取值合法
- [ ] 每条核心结论都标注来源编号，且编号在参考资料中存在
- [ ] 每条结论可被出处支撑，无凭空推断；推测性内容已标注"推测"
- [ ] 详细分析每节自包含，无跨节指代
- [ ] 参考资料每条含 URL/路径和访问日期
- [ ] 时效敏感的结论标注了版本号/时间条件
- [ ] 深度为"深度"时，关键结论有至少 2 个独立来源交叉验证
- [ ] 文档要求符合调研深度（快查：摘要+结论完整；标准/深度：全章节完整）
- [ ] tags 已填写且含至少一个细分主题标签（细分分类由 tags 承担，目录只到大类）

发现问题 → 修复后重新自检，直至全部通过。更新 `research-session-{主题}.md`。

**完成标准**：自检清单全部通过。

---

## 步骤4: 定稿确认

**目标**：用户审阅确认，文档定稿。

**操作**：

1. 向用户呈现草稿**文件路径 + 摘要**，请用户审阅
2. 用户提出意见 → 修订草稿（涉及新事实时回到步骤1补充来源），修订后再次自检（步骤3清单）
3. 用户确认定稿：
   - status 按实际定值：`已结论` / `跟进中`
   - 更新 `research-session-{主题}.md`：当前步骤 → `步骤4-已完成`，写入定稿摘要：

```
## 调研完成摘要

### 调研主题
{核心问题}

### 深度 / domain
{快查/标准/深度} / {domain}

### 结论与来源
- 核心结论数: N（推测性结论 N 条）
- 来源数: N

### 输出文件
{文件路径}

### 跟进项
{无 / 逐条列出}
```

4. 询问用户是否删除 `research-session-{主题}.md`（定稿后默认可删除）

**完成标准**：文档定稿，定稿摘要已持久化。

---

## 异常处理

| 情况 | 处理方式 |
|------|---------|
| 调研主题不明确 | 暂停工作流，向用户确认核心问题后继续 |
| 来源结论冲突 | 并列呈现 + 标注来源与适用条件，列入后续跟进，status=跟进中 |
| 信息不足以回答核心问题 | 如实标注缺口，不猜测补齐，与用户确认是否以"跟进中"状态定稿 |
| 用户审阅提出新事实 | 回到步骤1补充收集，修订后重新自检 |
| 任意阶段中断 | 会话文件已持久化，下次 `/research {同主题}` 触发步骤R 从断点恢复 |
| 同主题存在未完成会话但用户不要继续 | 经用户确认后删除该会话文件，按新参数重新执行步骤0 |
