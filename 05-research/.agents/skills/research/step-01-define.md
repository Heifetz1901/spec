# 步骤0: 界定问题

**目标**：明确调研要回答的问题、用途和边界，确定执行策略。确保进入步骤1前问题充分清晰。

**操作**：

1. 解析 `$ARGUMENTS`，理解调研意图，提炼**核心问题**（一句话可表述）
2. 逐项明确调研要素，存在歧义时向用户确认：
   - **核心问题**：要回答什么
   - **用途**：决策支撑 / 学习理解 / 操作指引
   - **时效敏感度**：结论是否依赖特定版本、时间窗口（如软件版本、政策、价格）
   - **domain**：按主题自然大类自由命名（不预设枚举）；执行目录对齐检查——已有相近子目录优先复用，目录名/粒度拿不准或与现有目录可能重叠时，单独询问用户确认
   - **调研深度**：快查 / 标准 / 深度（按 [references/depth.md](references/depth.md) 判定条件评估，拿不准时向用户确认）
3. **检索已有调研**：搜索输出目录下同主题/同关键词的既有调研文档
   - 存在相关文档 → 向用户确认：**更新旧文**（旧文基础上增量调研）还是**新建文档**
   - 新建且旧文被取代时，在旧文 frontmatter 的 `replaces` 字段标注新文档路径
4. 产出调研规划摘要，提交用户确认：

```
## 调研规划摘要

- 核心问题: {一句话}
- 用途: {决策支撑/学习理解/操作指引}
- 时效敏感度: {无/依赖版本X/政策时效等}
- domain: {tech/work/life}
- 调研深度: {快查/标准/深度}
- 输出文件: {输出目录}/{domain}/{主题}-YYYYMMDD.md
- 已有相关调研: {无 / 文件路径列表及处置方式}
```

5. 用户确认后：
   - 创建输出目录及 `{domain}` 子目录（不存在时）
   - 按 [assets/template.md](assets/template.md) 模板创建草稿文件（仅骨架，frontmatter 中 date 取当日，status 暂为 `跟进中`）
   - 创建会话文件 `research-session-{主题}.md`（主题与输出文档名一致），结构为：

```
当前状态（步骤+调研深度+更新时间）→ 调研规划摘要 → 指针（草稿路径/工作文件路径）→ 步骤执行记录（步骤0标记✓，步骤1-4标记待执行）
```

**完成标准**：调研规划摘要经用户确认，草稿文件与 `research-session-{主题}.md` 已创建并持久化。
