# 调研工作流同类规范与Skill调研

## 摘要

- Anthropic 官方 skills 仓库没有任何调研类 skill，research 类工作流全部由社区生态提供，本规范填补的是官方空白
- 最相似的三个同类：Weizhena/Deep-Research-skills（结构最像）、azagreev/DResearch-Skill（理念最像，证据台账+置信度评分）、Anjos2/recursive-research（持久化机制最像，磁盘检查点+来源分级）
- 本规范的调研深度分级、个人知识库中心设计、单一 Markdown 会话文件轻量断点恢复，三个特色在同类项目中均未见到
- 可借鉴机制：字段校验脚本、置信度评分、场景化搜索模块、来源 Tier 显式元数据化

## 问题与背景

- **核心问题**：本目录的调研工作流及模板规范，在互联网与 GitHub 上有没有类似的规范和 skill？
- **背景**：调研工作流以 Claude Code Skill 形式落地（`.claude/skills/research/SKILL.md`），核心设计包括：步骤 R/0→4 串行执行（恢复检查→界定问题→信息收集→分析成文→自检修订→定稿确认）、`research-session-{主题}.md` 会话持久化与断点恢复、编号化结论（C1、C2…）+ 来源编号追溯、三级调研深度（快查/标准/深度）、`~/workspace/research/` 个人知识库沉淀
- **用途**：学习理解 + 后续演进决策支撑（判断是否有必要参考同类项目的机制设计）
- **调研方式**：Web 搜索（中英文）+ GitHub 仓库检索（gh CLI / zread）+ 仓库目录逐一核对，2026-10-15 完成

## 核心结论

| C1 | Anthropic 官方 skills 仓库（anthropics/skills）只含 docx/pdf/pptx/mcp-builder/skill-creator 等文档与工具类 skill，无调研类 skill，调研工作流属社区生态空白区 | [21] |
| C2 | Weizhena/Deep-Research-skills 是结构上最相似的同类：命令族 `/research → /research-add-items → /research-add-fields → /research-deep → /research-report`，两阶段调研（先生成 outline.yaml + fields.yaml，再逐 item 深度调研），断点续传靠检查输出目录已完成 JSON 跳过，关键点用 AskUserQuestion 确认；但它是多对象横向对比型（items×fields 矩阵、输出结构化 JSON），与本规范的单问题深挖叙事型互补而非重复 | [1] |

## 详细分析

### 最相似的同类项目对比

三个最相似项目与本规范的机制对照：

| 机制 | 本规范 | Weizhena/Deep-Research-skills | azagreev/DResearch-Skill | Anjos2/recursive-research |
|------|--------|------------------------------|--------------------------|---------------------------|
| 关键点人工确认 | 问题界定、结论取舍、定稿向用户确认 | AskUserQuestion 确认 items/字段框架/批次 | 分阶段控制点 | 自主决策为主（WDM + Munger 逆向） |
| 断点续传 | research-session-{主题}.md 记录步骤状态，步骤R 恢复 | 检查输出目录已完成 JSON，跳过已完成 items | 中间状态与控制点 | 每循环保存磁盘 checkpoint，抗上下文压缩 |
| 并行收集 | 步骤内多来源派发多 Agent 并行 | batch_size 分批派发 web-search-agent，每批需用户同意 | 子任务拆分 | 递归展开 |
| 结论可追溯 | 编号化结论 + 来源编号标注 + 冲突并列 | 搜索模块返回信息来源 | 证据台账：结论关联支持/反驳来源，分歧显式呈现 | 来源 Tier 1/2/3 分级 |
| 输出形态 | 叙事性 Markdown 调研文档（个人知识库） | 结构化 JSON（items×fields 矩阵） | 结构化报告 + 置信度评分 | 递归调研报告 |

**Weizhena/Deep-Research-skills**（[1]）：面向 Claude Code / OpenCode / Codex，中英双语（research-zh / research-en 两套）。`/research` 基于模型内部知识生成初步框架（items 列表 + 字段框架），经 web-search-agent 补充后产出 outline.yaml（含 execution 配置：batch_size、items_per_agent、output_dir）与 fields.yaml（字段定义，detail_level 分层：极简→简要→详细，不确定字段留给 deep 阶段自动填充）。`/research-deep` 逐 item 派发后台 agent，输出 JSON 后运行 validate_json.py 校验字段完整覆盖。搜索 agent 按场景分模块：academic-papers / chinese-tech / general-web / github-debug / stackoverflow。

**azagreev/DResearch-Skill**（[2]）：俄语 Claude Code 插件（MIT），核心概念是证据台账——研究结论与来源、验证和置信度评估关联，分歧在报告中呈现。适用场景：市场/公司/技术/行业调研、多方案给定标准对比、复杂问题拆解为可验证论断。仓库含插件入口、Python engine、完整规范（SKILL.master.md）、编排示例和复盘清单。

**Anjos2/recursive-research**（[3][4]）：PhD 级递归调研 skill，跨领域（科学、技术、商业、艺术、人文）。三个机制：来源分级 Tier 1/2/3、加权决策矩阵（WDM）+ Munger 逆向用于自主决策、磁盘检查点每循环保存以在上下文压缩后存活。

### 本规范的独特性与定位

结合 C1–C5：本规范不是重复造轮子——官方无调研类 skill，社区同类要么面向学术文献（PRISMA/综述流程）、要么面向多对象横向对比（items×fields 矩阵）、要么面向一次性报告；以"日常咨询沉淀为个人知识库"为中心、带深度分级和版本链（replaces）的设计在检索范围内未见同类。与最接近的三个项目形成互补：Weizhena 适合多对象横评、DResearch 适合强验证场景、本规范适合单问题深挖并沉淀。
