# 测试用例设计 Skill

根据同目录下的 `测试用例设计规范.md` 为指定功能模块生成标准测试用例。

## 触发条件

- 用户提到"设计测试用例"、"写用例"、"测试用例"
- 用户提到"等价类"、"边界值"、"判定表"、"场景法"
- 用户提到"用例评审"、"覆盖度检查"
- 用户提到"测试计划"、"test case"

## 用例编号规则

```
TC-{模块代码}-{功能序号}-{用例序号}
```

- 模块代码：2-4位大写字母（如 ORD、PAY、USR）
- 功能序号：2位数字
- 用例序号：3位数字，顺序递增，不可复用
- 用例拆分追加后缀（如 TC-ORD-01-001-1）

## 优先级定义

| 优先级 | 定义 | 覆盖要求 |
|--------|------|---------|
| P0-冒烟 | 核心正向流程，阻断性功能 | 100% |
| P1-关键 | 主要业务场景，高频路径 | 100% |
| P2-一般 | 边界条件、异常路径、低频场景 | 80%+ |
| P3-边缘 | 极端场景、多条件组合 | 按需 |

## 设计方法选择

| 场景特征 | 推荐方法 |
|---------|---------|
| 单一输入，离散取值 | 等价类划分 |
| 单一输入，连续数值范围 | 边界值分析 |
| 多个条件组合决定结果 | 判定表 |
| 有明确业务流程 | 场景法 |
| 流程中含条件分支 | 场景法 + 判定表 |
| 流程中含数值计算 | 场景法 + 边界值 |

## 工作流程

### Step 1: 需求分析

1. 读取用户提供的功能需求/接口文档/PRD
2. 识别所有输入参数及其约束（类型、范围、必填、格式）
3. 识别业务流程和状态转换
4. 确定模块代码和功能序号

### Step 2: 设计方法选择

根据需求特征选择主设计方法，必要时组合多种方法：

- 有输入参数 → 先做**等价类划分**
- 有数值范围 → 补充**边界值分析**
- 有多条件组合 → 使用**判定表**
- 有业务流程 → 使用**场景法**覆盖端到端路径

### Step 3: 生成用例

按以下标准模板输出，按模块分组，同一功能的用例连续排列：

#### 标准模板

```
用例编号:    TC-{模块}-{功能}-{序号}
用例名称:    {条件+动作+预期}
优先级:      P0/P1/P2/P3
标签:        [{设计方法}] [{正向/逆向}]
前置条件:    {环境、数据准备、系统状态}

测试输入:
  | 参数 | 值 | 说明 |
  |------|----|------|
  | param1 | value1 | ... |

操作步骤:
  1. {步骤描述}
  2. {步骤描述}

预期结果:
  - {断言点1}
  - {断言点2}
  - {断言点3}
```

#### 简化模板（数据驱动场景）

当多条用例仅输入数据不同、操作步骤和预期结构相同时：

```
用例编号:    TC-{模块}-{功能}-001~N
用例名称:    {统一描述}
优先级:      P1
标签:        [等价类]
前置条件:    {公共前置条件}

测试数据:
  | 用例编号 | 输入参数 | 预期结果 | 备注 |
  |---------|---------|---------|------|
  | -001 | value1 | result1 | 有效等价类A |
  | -002 | value2 | result2 | 无效等价类 |
```

### Step 4: 断言编写

每条预期结果必须满足：

| 要求 | 说明 |
|------|------|
| 可验证 | 可明确判断通过/失败 |
| 具体化 | 明确字段值、数量、状态 |
| 完整性 | 覆盖所有可观察的变化 |
| 无歧义 | 不使用模糊表述 |

### Step 5: 覆盖度自检

生成用例后，逐项检查：

- [ ] 每条功能需求至少对应一条正向用例
- [ ] 每个输入参数的有效/无效等价类均已覆盖
- [ ] 每个数值型参数的边界值均已测试
- [ ] 判定表中每种条件组合均有对应用例
- [ ] 业务流程的正常流和主要异常流均已覆盖
- [ ] 异常输入（空值、超长、特殊字符、非法类型）均已测试
- [ ] 并发、幂等、超时等非功能场景已按需覆盖

### Step 6: 输出用例列表

最终以列表形式汇总所有用例：

```markdown
## 用例列表

### {模块名称}（{模块代码}）

| 用例编号 | 用例名称 | 优先级 | 标签 | 前置条件 | 测试输入 | 操作步骤 | 预期结果 |
|---------|---------|--------|------|---------|---------|---------|---------|
| TC-{模块}-01-001 | ... | P0 | 等价类 正向 | ... | ... | ... | ... |
```

## 常见测试场景参考

### 输入校验

- 必填字段：空值、空白字符、仅空格
- 数值范围：超下限、超上限、负数、零、极大值
- 字符串长度：空串、最小长度、最大长度、超长
- 格式校验：邮箱、手机号、身份证、日期格式
- 特殊字符：SQL关键字、HTML标签、引号、反斜杠
- 类型校验：数字字段传字符串、字符串字段传数字

### 接口测试

- 参数完整性：缺少必选参数、多传参数、参数名错误
- 参数类型：类型不匹配、null值、空数组
- 业务逻辑：正常流程、边界条件、异常分支
- 返回值：正确返回结构、错误码覆盖、分页边界
- 幂等性：重复请求、并发请求

### 状态转换

- 正向转换、跳步转换、逆向转换、非法转换、并发转换

### 数据处理

- 查询（精确、模糊、范围、排序、分页）
- 新增（唯一性冲突、关联数据不存在）
- 修改（并发修改、部分更新、不可修改字段）
- 删除（有关联数据、批量删除、重复删除）
