# 技术类设计文档生成 Skill

为公共库/组件开发需求生成标准技术设计文档。本 Skill 包含完整的工作流和文档模板，无外部依赖。

## 触发条件

- 用户提到"技术设计"、"技术方案"、"设计文档"
- 用户提到"架构设计"、"模块设计"、"接口设计"
- 用户提到"tech design"、"design doc"
- 用户需要为公共库/组件编写技术设计文档

## 适用场景

- 公共库/组件开发
- SDK、工具包、中间件设计
- 需要对外提供API的技术组件

## 总则约束

**应包含的内容：**
- ✅ 库的定位与职责 — 明确库的职能边界、背景目标、核心能力
- ✅ 总体架构与模块划分 — 整体架构设计、模块职责与依赖关系
- ✅ 数据流与核心数据结构 — 模块间调用时序、核心模型定义
- ✅ 模块设计 — 各模块的接口定义、内部类关系、实现逻辑
- ✅ 集成使用方式 — 依赖引入、初始化配置、使用示例
- ✅ 架构决策记录 — 关键技术/架构决策的背景与结论

**不应包含的内容：**
- ❌ 已有库的简单封装 — 仅做一层薄包装，无新增逻辑
- ❌ 工具类的逐一罗列 — 通用工具函数无需逐一设计
- ❌ 具体实现代码 — 除核心算法、使用实例以外，不应包含具体的业务实现代码

## 团队角色

| 角色 | 职责 |
|------|------|
| 负责人 | 整体文档规划、需求分析、审核确认 |
| 架构师 | 总体架构、模块划分、架构决策 |
| 模块负责人 | 各模块的接口设计、实现逻辑编写 |
| 评审人 | 文档质量评审、一致性检查 |

## 工作流程

### Step 1: 需求分析（负责人）

1. 读取用户提供的需求数据（PRD、需求文档、issue 等）
2. 识别库/组件的定位：解决什么问题、使用场景
3. 向用户确认需求理解是否正确
4. **确定团队分工**：分配各章节负责人

### Step 2: 信息收集（支持并行）

**串行前置**（必须先完成，确定整体框架）：
- 4.1 总体架构、4.2 模块划分 — 确定架构和模块边界

**可并行收集**（依赖 Step 1，彼此独立）：
- 并行组A：3. 需求概述 + 4.3 数据流 + 4.4 核心数据结构
- 并行组B：4.5 线程模型（可选）
- 并行组C：7. ADR 收集

**依赖4.2模块划分后并行**：
- 5.x 各模块设计（每个模块独立，可按模块分配给不同负责人）
- 6. 快速开始

对于用户未提供的信息，主动提问或标注为待补充。

### Step 3: 生成文档（支持并行）

1. 基于下方模板创建新文档
2. **按并行组生成内容**：
   - 组1（并行）：各模块 5.x 设计 — 每个模块可由不同 Agent 同时编写
   - 组2（并行）：第4章各子章节 — 架构、数据流、数据结构可同时生成
   - 组3（独立）：第6章 快速开始 — 不依赖其他章节
3. 合并并行结果到主文档
4. 对于示例性内容（标注为 `*如：xxx*`），替换为实际内容
5. 保留未确定项的占位符，并标注 `<!-- TODO -->`
6. 确保目录锚点与正文标题一致

**并行执行示意：**

```
Step 1: 需求分析 + 团队分工
         ↓
Step 2: 4.1架构 + 4.2模块划分（串行前置）
         ↓
    ┌────┼────────────┐
    ↓    ↓            ↓
  组A  组B(模块)    组C(快速开始)
  4.3  5.1, 5.2...   6.1~6.3
  4.4
    ↓    ↓            ↓
    └────┼────────────┘
         ↓
Step 4: 合并 + 自检
```

### Step 4: 自检清单

- [ ] 目录与正文章节一一对应，锚点可跳转
- [ ] 总则1.1"应包含内容"与实际7个章节一致
- [ ] 无具体实现代码（核心算法、使用实例除外）
- [ ] 表格、代码块格式正确
- [ ] 所有 `*如：xxx*` 示例已替换或标注待补充
- [ ] 接口签名、模块依赖关系完整
- [ ] 快速开始章节可独立运行

### Step 5: 评审确认

1. 负责人汇总各章节内容，检查整体一致性
2. **交叉评审**：模块负责人互相评审对方的模块设计
3. 确认无遗漏后提交最终版本

## 6. 快速开始

> 提供最快速的接入指南，帮助调用方在几分钟内完成引入和基本调用。

### 6.1 引入依赖

**Maven**

```xml
<!-- *如：* -->
<dependency>
    <groupId>*com.example*</groupId>
    <artifactId>*order-service*</artifactId>
    <version>*1.0.0*</version>
</dependency>
```

**Gradle**

```groovy
// *如：*
implementation '*com.example:order-service:1.0.0*'
```

### 6.2 初始化配置

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| *如：order.timeout* | *int* | *30* | *订单超时时间（秒）* |
| *如：order.maxRetry* | *int* | *3* | *最大重试次数* |

```java
// *如：手动初始化示例*
OrderService orderService = OrderService.builder()
    .timeout(60)
    .maxRetry(3)
    .build();
```

### 6.3 使用示例

```java
// *如：*
OrderContext context = new OrderContext()
    .setUserId("U001")
    .addOrderItem(new OrderItem("商品A", 2));

OrderResult result = orderService.create(context);
System.out.println(result.getOrderId()); // ORD-20240001
```
