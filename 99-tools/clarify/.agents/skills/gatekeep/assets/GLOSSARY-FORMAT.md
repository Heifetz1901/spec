# GLOSSARY.md 格式

## 结构

```
# {上下文名称}
{一两句：这个上下文是什么、为何存在}

## 术语

**术语（原词）**:
{一两句术语定义：是什么，不是做什么}
_避免_: 同义词清单

**发票（Invoice）**:
交付后向客户发出的付款请求。
_避免_: 账单（Bill）、付款请求（payment request）

**客户（Customer）**:
下单的个人或组织。
_避免_: 客户（Client）、买家（buyer）、账户（account）
```

示例条目仅示格式；术语与定义必须来自当前项目的对话与代码，不得沿用示例内容。

## 规则

- **有主见**。同一概念存在多个词时，选最好的一个，其余列入 `_避免_`。
- **定义收紧**。最多一两句。定义它「是什么」，不是「做什么」。
- **只收本项目特有的术语**。通用编程概念（超时、错误类型、工具模式）即使项目大量使用也不收。添加前自问：这是本上下文独有的概念，还是通用编程概念？只有前者收录。
- **自然聚类时分小节**。术语形成自然群组时用子标题分组；若全部属于单一领域，平铺即可。

## 单上下文 vs 多上下文

单上下文（多数仓库）：仓库根一个 `GLOSSARY.md`。
多上下文：根目录 `GLOSSARY-MAP.md` 列出各上下文、位置及相互关系（格式见 GLOSSARY-MAP-FORMAT.md）。
推断：存在 `GLOSSARY-MAP.md` → 读它找上下文；只有根 `GLOSSARY.md` → 单上下文；两者皆无 → 第一个术语落定时懒创建根 `GLOSSARY.md`。多上下文时，推断当前话题关联哪个上下文；不清楚就问。
