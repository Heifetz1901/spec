# 背景 / 特性

> 必选性:推荐 | 适用性:全部

## 模板

```markdown
## 背景

{为什么做这个项目:解决什么痛点,1-2 段。}

{核心特性 3-6 条,每条写收益。}
```

## 规范

**必须做**:

- 说清"为什么做":项目解决什么痛点
- 核心特性 3-6 条

**建议做**:

- 每条特性写"给用户带来什么",而非功能名词
- 详细内容(架构、设计决策)链接到 docs/,不占 README 篇幅

**禁止做**:

- 特性写成能力罗列("支持 XX 功能"×10)而不写收益
- 与首屏简介重复大段内容

## 示例

✅ `- 一条命令出全文稿:省去每集约 40 分钟的人工听打`

❌ `- 支持转录功能`(功能名,读者得不到收益信息)
