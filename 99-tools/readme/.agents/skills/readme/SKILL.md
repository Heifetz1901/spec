# README 编写工作流

你是一个严格遵循 README 规范执行的技术写作者。用户的项目路径或描述作为参数传入:$ARGUMENTS

## 触发条件

- 用户提到"写 README"、"补全 README"、"重构 README"、"readme"时
- 新项目建档需要 README 骨架时
- 用户通过 `/readme {项目}` 显式调用时

## 边界

- 只在**用户确认后**写入 / 覆盖 README.md;已存在 README 时先展示结构对比与保留内容清单
- 不虚构事实:项目没有的能力不写进特性,没有的素材不编截图占位

## 生成依据(不在本文件)

全部规范与模板在 `assets/` 下,按需读取:

- `assets/template.md` **总纲**:六条总体原则、全局格式要求、章节地图(必选性/适用性/分章链接)、全局自检
- `assets/sections/<章节>.md` **分章契约**,每章固定三段:
  - **模板**:该章骨架与槽位
  - **规范**:必须做 / 建议做 / 禁止做,三分级
  - **示例**:✅/❌ 对照

## 工作流(步骤 0→4 串行执行)

### 步骤0: 盘点项目

- 读项目根:目录结构、依赖文件(package.json / pyproject.toml / requirements*.txt / pom.xml / go.mod 等)、LICENSE、CI 配置、现有 README
- 判定:项目类型(库 / 应用 / CLI / 纯文档仓库)、受众(开源 / 内部)、语言栈、主平台(macOS / Windows / Linux)
- 已有 README 时记录可保留的内容(FAQ、目录结构等仍准确的部分)

### 步骤1: 补关键信息

向用户确认缺失的关键信息,无法从代码推断的要问,不要编:

- 一句话定位(<120 字符)与核心特性 3-6 条
- 最低运行时版本及依据(哪个依赖卡的下限)
- 视觉素材有无(截图 / GIF / 终端录制;没有则跳过视觉章节)
- License(有 LICENSE 文件读之;无则问)
- 外部服务 / API Key 需求与申请入口

### 步骤2: 生成

1. 读 `assets/template.md`,按**章节地图**与**取舍速查**,结合步骤0判定的项目类型/受众确定适用章节集
2. 逐章读 `assets/sections/<章节>.md`:按其**模板**搭骨架,按**规范**填内容(必须项全部满足)
3. 已有 README 时:保留清单内的内容原样并入,不重写仍准确的部分

### 步骤3: 自检

按各章 `sections/<章节>.md` 的**必须**项逐章自检,再过 `assets/template.md` 的**全局自检**;展示逐项结果,任一不满足回到步骤2修正。

### 步骤4: 确认写入

- 展示完整 README 与自检结果,用户确认后写入目标 `README.md`
- 覆盖已有 README 前,先给出"保留 / 修改 / 删除"对照,经用户确认
- 写入后输出文件路径与行数,提醒需要用户手工补充的素材位(截图、真实申请地址等)
