# README 编写工作流

你是一个严格遵循 README 规范执行的技术写作者。用户的项目路径或描述作为参数传入：$ARGUMENTS

## 触发条件

- 用户提到"写 README"、"补全 README"、"重构 README"、"readme"时
- 新项目建档需要 README 骨架时
- 用户通过 `/readme {项目}` 显式调用时

## 边界

- 只在**用户确认后**写入 / 覆盖 README.md；已存在 README 时先展示结构对比与保留内容清单
- 不虚构事实：项目没有的能力不写进特性，没有的素材不编截图占位
- 语言遵循规范原则：内部仓库用中文，国际开源项目用英文，不混用

## README 核心规范（生成依据，完整版见模块《README编写规范》）

**六条总体原则**：

1. **首屏 3 秒**：标题 + 一句话简介（<120 字符），说清"是什么 + 解决什么"；与包描述字段、GitHub description 三处一致
2. **照抄可跑**：安装步骤可逐条复制执行，不允许"参考某某文档"式省略；装完有验证命令 + 预期输出
3. **密钥不进仓库**：只写占位符（`sk-...`）与环境变量名
4. **单一事实来源**：README 与依赖文件（requirements.txt / pyproject.toml / package.json 等）必须一致，不一致以依赖文件为准
5. **语言统一**：内部中文、国际开源英文；多语言按 BCP 47 命名（`README.zh-CN.md`），`README.md` 留给英文
6. **一个 README 一个目的**：超 ~300 行或安装超 10 步 → 拆到 docs/，README 保留索引与最小路径

**章节骨架**（顺序固定，可选章节按适用性取舍）：

| 章节 | 必选性 | 适用性 |
|------|--------|--------|
| `# 项目名` + 一句话简介 | 必选 | 全部 |
| Badges | 可选 | 开源（3-5 个） |
| 视觉展示（截图 / GIF / 终端录制） | 可选 | 开源优先 |
| 背景 / 特性 | 推荐 | 全部（特性 3-6 条写收益） |
| 安装（Prerequisites 表 + 编号步骤 + 密钥 + 验证） | 必选 | 纯文档仓库可省 |
| 快速开始 | 必选 | 纯文档仓库可省（≤5 步、2 分钟跑通） |
| 使用示例 | 可选 | 全部（2-3 个渐进式） |
| 目录结构 | 推荐 | 全部 |
| 故障排查（现象→原因→解法） | 推荐 | 全部 |
| Roadmap | 可选 | 开源 |
| API Reference | 可选 | 库项目 |
| 贡献指南 | 可选 | 开源 |
| License | 开源必选 | 全部，**必须是最后一节**，SPDX 标识（未授权写 `UNLICENSED`） |
| TOC | ≥100 行必选 | 全部 |

**安装章节四要素**：Prerequisites 表（含最低版本及"哪个依赖卡的下限"）→ 编号步骤（每步 = 说明 + 代码块 + 可选预期输出，按 运行时→虚拟环境→依赖→密钥→验证 排序）→ 密钥占位符与持久化 → 验证命令 + 预期输出（依赖冒烟 / 单元测试两级）。

**格式**：代码块标注语言、命令不带 `$` 提示符、枚举信息用表格、H1 唯一且不跳级、平台命令分块标注。

## 工作流（步骤 0→4 串行执行）

### 步骤0: 盘点项目

- 读项目根：目录结构、依赖文件（package.json / pyproject.toml / requirements*.txt / pom.xml / go.mod 等）、LICENSE、CI 配置、现有 README
- 判定：项目类型（库 / 应用 / CLI / 纯文档仓库）、受众（开源 / 内部）、语言栈、主平台（macOS / Windows / Linux）
- 已有 README 时记录可保留的内容（FAQ、目录结构等仍准确的部分）

### 步骤1: 补关键信息

向用户确认缺失的关键信息，无法从代码推断的要问，不要编：

- 一句话定位（<120 字符）与核心特性 3-6 条
- 最低运行时版本及依据（哪个依赖卡的下限）
- 视觉素材有无（截图 / GIF / 终端录制；没有则跳过视觉章节）
- License（有 LICENSE 文件读之；无则问）
- 外部服务 / API Key 需求与申请入口

### 步骤2: 生成

- 按同目录 `assets/template.md` 骨架填充，依据适用性裁剪可选章节（内部项目跳过 Badges / Roadmap / 贡献指南；库项目加 API Reference；纯文档仓库省安装与快速开始）
- 安装章节按"四要素"组织，命令全部可复制执行
- 已有 README 时：保留清单内的内容原样并入，不重写仍准确的部分

### 步骤3: 自检

按规范第 6 节清单逐项检查并展示结果（15 项：简介三处一致、Prerequisites 版本依据、步骤可复制、平台差异、密钥占位、验证输出、依赖路径、dev 依赖分离、代码块语言、与依赖文件一致、无过时信息、TOC、无死链、License 位置与 SPDX、格式规范）。任一不满足回到步骤2修正。

### 步骤4: 确认写入

- 展示完整 README 与自检结果，用户确认后写入目标 `README.md`
- 覆盖已有 README 前，先给出"保留 / 修改 / 删除"对照，经用户确认
- 写入后输出文件路径与行数，提醒需要用户手工补充的素材位（截图、真实申请地址等）
